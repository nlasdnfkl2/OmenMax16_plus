# OMEN MAX 16 Control Center 개발 현황 및 로드맵

## 1. 개요
본 문서는 **OMEN MAX 16 Control Center**(`Form.html` 기준 WebView2 기반 프론트엔드 및 제어 인터페이스)의 현재까지의 개발 진척도, 주요 구현 기능, 향후 모델 확장 방향, 그리고 현재 기술적 한계를 정리한 문서입니다.

---

## 3. 현재 구현된 주요 기능

### 3.1. 실시간 텔레메트리 및 상태 인디케이터
- **CPU 모니터링**: 사용률(`%`), 소비 전력(`W` 및 상한 대비 비율), 클럭(`GHz`), 온도(`°C`), 전압(`V`), FPS(`fps`) 표시 및 부드러운 보간(`useSmooth`) 적용.
- **GPU 모니터링**: 활성/미검출/비활성 상태 처리, 온도(`°C`), 클럭(`GHz`), 사용률(`%`), 소비 전력(`W`) 표시 및 고성능 프로필 시 강조 효과 적용.
- **통합 상태 인디케이터(`StatusDot`)**: CPU 온도, GPU 온도, CPU 전압 임계치를 종합해 `정상` / `주의` / `경고` / `위험` 4단계 상태 색상 및 점멸 주기로 표시.
- **배터리 제어**: 배터리 잔량(`%`), 충·방전 전력(`W`), 충전 상태 펄스 효과 및 배터리 잠금(`TOGGLE_BATTERY_LOCK`) 토글 제공.

### 3.2. 전력 제어 및 팝업 (`CPU 전력` / `GPU`)
- **CPU 전력 제어 팝업**:
  - `15~160W` 범위의 `PL1`(지속 전력), `PL2`(부스트 전력), `Tau`(부스트 유지 시간, `1~56초`) 슬라이더 제어.
  - 프리셋(`저전력`, `정숙 게임`, `균형 게임`, `고성능 게임`, `최대 성능`) 지원.
  - `TPP 250W 게이밍 동적 배분` 토글 및 동시 부하 시 CPU 전력 상한(`55~105W`) 슬라이더 제공.
- **GPU 전력 제어 팝업**:
  - `cTGP 확장` 및 `Dynamic Boost (PPAB)` 토글, GPU 클럭 상한(`MHz`) 프리셋 및 슬라이더(`1200~2800MHz`), GPU 끄기(`SET_GPU_MODE`, `-1`) 및 적용(`SET_GPU_CLOCK_CAP`) 지원.
  - 클럭 기반 예상 소비 전력 환산 테이블(`CAP_TABLE` / `estWatts`) 내장.

### 3.3. 팬 제어 및 커브 편집기
- **팬 상태 및 모드**: `CPU FAN`, `GPU FAN`의 RPM 및 `%` 표시, 팬 회전 속도 연동 애니메이션, `QUIET`/`COOL` 모드 시 동기화(`SYNC`) 배지 표시.
- **팬 커브 편집기(`#curve-modal`)**: `35°C~100°C` / `0%~100%` 좌표계에서 클릭 추가, 드래그 이동, 우클릭 포인트 삭제, `CPU 팬 커브` / `GPU 팬 커브` 탭 전환, `QUIET` / `COOL` 커브 저장 메시지(`SAVE_QUIET_CURVE`, `SAVE_CUSTOM_CURVE`) 전송 지원.

## 4. 향후 개발 방향 (타겟 모델 및 GPU 확장)

현재 단일 구성 위주로 작성된 하드웨어 라벨, 전력 범위, 클럭-전력 매핑, 동적 전력 배분 로직을 **OMEN MAX 전체 주요 라인업**으로 확장합니다.

1. **CPU 라인업 확장**
   - **Intel Core Ultra 9 275HX** (기존 기준 유지)
   - **AMD Ryzen AI 7 350** 계열 모델 추가
   - **AMD Ryzen AI 9 HX 375** 계열 모델 추가
   - CPU 모델별 기본/최대 `PL1`·`PL2`·`Tau` 범위 및 전압/전력 표기 동적 구성.

2. **GPU 라인업 확장 (`RTX 5060 ~ RTX 5090`)**
   - **RTX 5060**, **RTX 5070**, **RTX 5070 Ti**, **RTX 5080**, **RTX 5090** Laptop GPU 모델별 명칭, 기본 TGP / cTGP / Dynamic Boost 상한, 클럭-전력 추정 곡선(`estWatts`) 테이블 분리 및 자동 매칭.

3. **통합 전력 예산(TPP / Total Platform Power) 동적 대응**
   - 모델 및 어댑터/섀시 사양에 따라 달라지는 총 플랫폼 전력 예산과 CPU-GPU 간 동적 전력 배분 상한을 하드코딩 대신 하드웨어 프로필 데이터 기반으로 계산.

---

## 5. 현재 한계점

1. **하드웨어 사양 및 상수의 `275HX + RTX 5070 Ti` 편중**
   - UI 표기(`Ultra 9 275HX`, `RTX 5070 Ti`), 전력 상한(`15~160W`, `140~175W`), `TPP 250W` 문구 및 `CAP_TABLE` 전력 추정치가 `275HX + 5070 Ti` 구성에 맞춰져 있어 다른 CPU/GPU 조합에서는 정확한 상한이나 예상 전력값이 나오지 않을 수 있습니다.
2. **호스트(`WebView2` C# 백엔드) 스키마 의존성**
   - 프론트엔드는 `d.cpu`, `d.gpu`, `d.fan`, `d.battery`, `d.ui` 메시지 구조와 커맨드(`OPEN_CPU_POWER`, `SAVE_CPU_POWER`, `SET_GPU_POWER`, `SET_GPU_CLOCK_CAP` 등)를 전제로 동작하므로, 신규 CPU/GPU 모델의 센서·전력 제어값을 내려주기 위한 C# 백엔드 및 레지스트리/EC/드라이버 계층 연동이 함께 뒷받침되어야 합니다.
3. **단일 파일(`Form.html`) 구조의 유지보수 부담**
   - 스타일, React 컴포넌트, 모달 상태, 팬 커브 SVG 스크립트가 한 HTML 파일에 모여 있어 모델별 프로필 테이블과 예외 처리가 늘어날수록 코드 가독성과 테스트 관리 비용이 커질 수 있습니다.
